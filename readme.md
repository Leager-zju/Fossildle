# Fossildle

每天发现一枚像素化石，把一点偶然放进你的私人博物馆。

- [开始游戏](https://leager-zju.github.io/Fossildle/)
- [GitHub 仓库](https://github.com/Leager-zju/Fossildle)

Fossildle 是一个以随机图案、结构发现和收藏为核心的轻量网页游戏，灵感来自 [RNGdle](https://www.rngdle.com/)。项目使用 React、TypeScript、Vite 和 SVG，完全静态，可部署到 GitHub Pages，无需后端或账号。

## 玩法与功能

1. 点击「发现今日化石」，敲开岩石。
2. 8×8 图案从上到下逐行揭晓。同一次页面会话内，切到图鉴、藏馆等页面不会暂停进度；返回时保留当前进度，已完成的标本不再自动重播。点击重播按钮可重新播放，不重新抽取。
3. 命中的结构按实际得分从低到高依次出现，新条目放在顶部；全部揭示结束后显示最终结构分和整体稀有度。
4. 点击结构条目，相关化石格保留原色，无关格置灰；再次点击取消选择。当条目的证据由多组构成时（多个连通块、多个空洞、左右/上下半场、四个象限、成对的对边），各组使用不同颜色区分，便于看清数量差与分组。局部图案若在同一枚标本上多处成立（「任意 N×M 窗口」或「存在一个独立遗骨」），只标注最靠上、最靠左的一处，不会把全部命中区块一起点亮；「至少 N 个」类结构仍会标出全部证据。
5. 在藏馆中回看、筛选、珍藏化石，或分享只读链接和 PNG 图片。点击卡片会按分享弹窗的样式居中预览这枚化石（图案、名称、稀有度、结构分与命中结构），不再跳转到今日发现；需要完整观察手记时，可从结构图鉴的「首次发现」链接进入。
6. 可选：用 GitHub 访问令牌把藏馆同步到自己的私有 Gist，换设备继续收集。不登录也能完整游玩（见下文「云同步」）。
7. 可选：连接 GitHub 账号后参与「每日排行」。榜单按结构分排出今日名次，UTC 00:00（北京时间 08:00）自动重置（见下文「每日排行」）。

图鉴包含 **99 项计分结构**，每项均有由命中概率标定的正整数基础分。其中 16 项为更容易遇见的常见结构，包括拾光石钩、小舟破浪、石上新芽、晶旁孤星、展翼小蛾、山口石鞍、地心余火与岸线反差；另有 22 项按「同形状递进」组成正向/斜向十字、实心方阵、空心方框、平行贯穿与十字贯穿等家族层级。稀有度依据实际模拟频率，不手工指定等级。覆盖连通星群、空洞秘境、对称回声、贯穿脉络、空间布局、组合奇遇、几何遗形、地层纹理、边界风景和疏密节律十类。支持发现状态、稀有度、类别联合筛选，编号/已发现名称搜索和稀有度排序。

未发现条目使用统一灰色样式并隐藏名称和条件，已发现条目按自身稀有度着色；卡片右侧显示该结构的概率标定分值。解锁后点击卡片会弹出居中示例窗口，用内置标准示例位图展示该结构，多组证据按不同颜色区分并附分组图例，局部图案同样只标注最靠上、最靠左的一处，窗口内也可跳转到首次发现记录。

观察手记中，同一形状族的层级互为上下位：存在至少该规模的强级一定蕴含弱级，被上位结构覆盖的下位结构不计分，其余结构各自独立计入总分。被上位结构覆盖的命中项会收进该项下方的可展开分支，灰调弱化并采用更小字号（仍会解锁图鉴），因组合加分上限而未计分的条目则单独平铺显示。全部命中结构统一逐项揭示，并可点击查看实际命中的格子。计分条目和图鉴卡片的底色、边框与交互状态均随结构稀有度变化。命中条目多于 16 项时，逐项揭示节奏会加快，计分阶段控制在约 11.2 秒内，不省略条目。旧藏品及分享页均按原位图使用当前评分 v4 重新计分；原位图、日期、生成版本、珍藏标记和随机生成方式不变。

**后续扩展约定：**所有新增结构必须配置正整数分值并参与统一计分，不允许新增仅观察、不计分的条目。增加结构、改变分组或分值时，需升级评分版本并重新校准两代生成器的整体分布；规则清单一致性测试会阻止使用过期概率表。

## 生成与计分规则

- **当前生成器为 v2**：使用浏览器安全随机源的 64 个随机位，每个像素独立以 1/2 概率成为化石，以 1/2 概率留白。
- 不限制化石像素数量，不做对称保底，也不因图案普通、全空或全满而重新抽取。
- 每天一枚，以 UTC 日期为准，UTC 00:00 更新，即北京时间 08:00。当天结果先保存再播放动画，刷新或重播不会重新抽取。
- 化石连通使用四邻接；空白区域使用八邻接。无法连到棋盘边缘的空白区域才算空洞。
- 每项结构的基础分由其在当前生成器中的命中概率标定：概率越低，分值越高，取值范围约 1–40 分。
- 结构分按「上下位」计算：同一形状族内只计最强的上位结构，其余下位结构不计分；不同族之间各自独立相加。组合加分总额最多 12 分。未计入总分的下位结构仍会显示并解锁图鉴。
- 独立模型下，全局对称结构极其罕见；局部结构更常见，但不存在得分保底或隐含补偿机制。

### 两种稀有度

- **整体稀有度**：参考对应生成器版本的百万份模拟样本，估计得到同分或更高分的概率，不是玩家排名或具体位图出现的概率。
- **结构稀有度**：依据结构自身的命中概率，与本次是否计分无关。可解析的 v2 结构使用理论概率，其余参考模拟频率；零观测项目按 95% 单侧概率上界暂定等级，不把零观测解释为零概率。

两者使用「常见、特别、稀有、珍奇、典藏」五档。结构评分规则为 **v5**，全部藏品和旧分享统一按当前规则重新计分，分数与整体稀有度可能变化；各自仍使用所属生成器的概率模型。旧位图、生成版本和分享链接保持不变。

## 本地开发

### 环境

- Node.js **22.12.0 或以上**，推荐 Node.js 24 LTS。
- npm。
- 使用本地辅助脚本时需要 Python **3.10 或以上**，仅使用标准库，无需安装 Python 依赖。
- 自动释放端口依赖系统工具：macOS/Linux 使用 `lsof`，Windows 使用 `netstat` 和 `taskkill`。下列命令以 macOS/Linux 为例。

在项目根目录执行：

| 用途 | 命令 |
|---|---|
| 开发热更新并打开浏览器 | `python3 local.py dev --open` |
| 开发详细日志 | `python3 local.py dev --debug --open` |
| 开发并解锁全部结构图鉴 | `python3 local.py dev --unlock-all` |
| 构建本地版本 | `python3 local.py build` |
| 构建带 source map 的调试版本并预览 | `python3 local.py preview --debug --open` |
| 仅预览已有产物，无需 Node | `python3 local.py preview --skip-build` |
| 查看全部选项 | `python3 local.py --help` |

缺少前端构建依赖时，脚本自动执行 `npm ci`；传入 `--install` 可按锁文件重装。

- 开发地址：`http://127.0.0.1:5173/`。
- 静态预览地址：`http://127.0.0.1:4173/Fossildle/`，模拟 Pages 子路径与真实 404 行为。
- 可通过 `--port`、`--host`、`--base-path` 调整服务；按 Ctrl+C 停止。
- 用浏览器开发者工具调试前端。`--debug` 构建提供 TS/TSX source map。

### 本地模式注意事项

**端口自动清理：** `dev` 和 `preview` 启动前会停止占用目标 TCP 端口的监听进程，包括其他项目的服务。先正常终止，超时再强制终止；不会自动提权。纯 `build` 不处理端口。

**调试存档重置：** 每次通过 `local.py` 启动开发服务或重新构建，会生成新的本地版本标识。浏览器首次加载该版本时，清空本应用的本地收藏并更新身份，以便重新抽取。同版本刷新、热更新及 `--skip-build` 不重复重置。此行为仅在本机或私网地址生效，不影响正式站点；需保留本地收藏时请先备份。

**解锁全部结构图鉴：** 附加 `--unlock-all` 会让图鉴（含藏馆统计与页脚进度）显示为全部解锁，便于逐项查看结构与示例图案，默认关闭。它同样只在 `localhost` 与私网地址生效，公网域名下自动失效；`--skip-build` 无法携带该开关（需重新构建），纯 `build` 也不接受它，`dev` 与 `preview` 可用。

也可直接使用 npm，不启用 Python 脚本的自动端口清理与本地版本重置：

```sh
npm ci
npm run dev
```

### 日志

## 构建与部署

正式构建使用普通 npm 命令：

```sh
npm ci
npm run build
```

产物位于 `dist/`。不要把带本地重置标识和 source map 的调试产物作为正式发布包；应重新执行正式构建。

### GitHub Pages

1. 将本项目内容放在 GitHub 仓库根目录，而不是再套一层项目文件夹。
2. 在仓库 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。
3. 向 `main` 或 `master` 推送，或在 Actions 中手动运行 `Deploy Fossildle to GitHub Pages`。
4. 工作流安装依赖、运行前端单元测试、构建并发布 `dist/`。

部署配置：`.github/workflows/deploy.yml`。Vite 使用相对资源路径，页面及只读分享使用 Hash 路由，兼容 `https://<用户>.github.io/<仓库>/` 形式的仓库子路径。

## 存档与限制

收藏默认只保存在当前浏览器的 `localStorage`。不同浏览器、域名和端口的记录互不共享；清除网站数据或使用无痕模式可能丢失记录。

在「关于」中可导出 JSON 备份并恢复，也可「重置存档」清空全部发现与珍藏标记并生成新的本地身份（二次确认后执行，无法撤销，重置前可先导出备份）。**导入与重置都会替换当前藏馆和本地身份，不会自动合并**；备份包含本地身份信息，请勿公开。

### 云同步（可选，仍然没有服务器）

顶部导航右侧的云图标可以接入 GitHub 账号，把藏馆同步到你**自己的私有 Gist**，实现跨设备继续收集：

1. 打开 GitHub 的 [新建访问令牌](https://github.com/settings/tokens/new?scopes=gist&description=Fossildle%20%E4%BA%91%E5%90%8C%E6%AD%A5) 页面，勾选 `gist` 权限（细粒度令牌则给 "Gists: Read and write"），生成后复制。
2. 在账号面板粘贴令牌并登录。首次登录会新建（或复用）私有 Gist `fossildle-collection.json`，并把云端与本地藏馆合并后回写。
3. 之后本地改动会在 1.5 秒后自动推送；在其他设备打开时会自动拉取合并。合并规则：同一天两处都有时**以云端图案为准**，珍藏标记取并集，仅本地存在的日期补入。

边界与安全：

- 浏览器无法直接完成 GitHub OAuth 授权（官方不支持 OAuth 端点的 CORS 预检），因此这里使用访问令牌；令牌只保存在本机 `localStorage`，且只发往 `api.github.com`。
- 云端是普通文件，**没有服务端签名与校验**：能编辑 Gist 的人就能改藏馆。它解决的是跨设备续玩，不是防作弊。
- 「断开连接」只清除本机令牌，云端 Gist 保留；「删除云端存档并断开」会删除该 Gist。也可以随时在 GitHub 上手动删除。
- 已连接时「重置存档」会把空存档推送到云端，云端记录一并清空。

分享链接只携带所选化石的日期、位图和生成版本，不包含整座藏馆。除「每日排行」外，项目是纯静态游戏，无法阻止修改时钟、编辑存档或构造分享链接，因此不提供服务器认证与防作弊竞技排名。

## 每日排行（可选，需要部署一个 Worker）

**定位：运气榜。** 每人每天拿到的化石不同，比的只是当天的手气；登录 GitHub 才能上榜，榜单公开每人的 GitHub 名字与头像。分数由服务端计算，客户端无法提交或修改分数。

数据流（三级可信）：

1. 客户端 `POST /api/play`，服务端用 `HMAC(SERVER_SECRET, login|date|generatorVersion)` 签发**当日种子**并落库；同一人同一天只会拿到同一个种子。
2. 客户端用 `generateSeededFossil(seed)` 在本地复现这枚化石（派生方式与 `scripts/calibrate.ts` 完全一致，因此概率与稀有度数据无需重新校准）。
3. 开箱后客户端只提交「今天」这一事实，服务端用自己的种子重建图案、重算分数与稀有度并写入榜单。因此改日期、换图案、重复抽取都无效。

每天自动重置靠**按 UTC 日期分桶**完成（不需要定时任务）；Cron Trigger 只做 90 天前的数据清理。

### 部署步骤

配置在仓库根目录的 `wrangler.toml`，因此所有 `wrangler` 命令都能直接运行，**顺序不能颠倒**（Worker 必须先存在才能设置密钥）：

```sh
npx wrangler login
npx wrangler d1 create fossildle-rank     # 把输出的 database_id 填进根目录 wrangler.toml
npm run worker:migrate                    # 在远端建表与索引
npm run worker:deploy                     # 创建并部署 Worker（得到 https://fossildle-rank.<账号>.workers.dev）
npm run worker:secret -- SERVER_SECRET    # 提示后粘贴一串长随机值，用于派生每日种子
```

也可以等价地写成 `npx wrangler deploy` / `npx wrangler secret put SERVER_SECRET`。

本地联调：`printf 'SERVER_SECRET=local-dev-secret\n' > .dev.vars` 后运行 `npm run worker:migrate:local` 与 `npm run worker:dev`，即可在 `http://127.0.0.1:8787` 上跑真实的 Worker + 本地 D1（`.dev.vars` 已在 `.gitignore` 中）。

然后把前端指向该地址构建（CI 里设为环境变量即可）：

```sh
VITE_FOSSILDLE_API=https://fossildle-rank.<账号>.workers.dev npm run build
```

未设置 `VITE_FOSSILDLE_API` 时，「每日排行」页会提示未配置，其余功能完全不受影响。本项目已部署的地址写在 `.github/workflows/deploy.yml` 的构建环境变量里；本地开发可复制 `.env.example` 为 `.env.local` 后直接启用。

如果正式站点换成了自定义域名，记得把该来源加进 `wrangler.toml` 的 `ALLOWED_ORIGIN`（多个用逗号分隔）并重新 `npm run worker:deploy`，否则浏览器会因跨域被拦下。

### 免费额度与边界

- 额度：Workers 免费 10 万请求/天；D1 免费 500 万行读、10 万行写、5GB 存储。每个请求只碰个位数行（签发 1 读 1 写、提交 3 读写、榜单 50 行），足以支撑每日数万次访问。
- **注意**：2026-09-01 起 Workers 免费账号一旦用完 D1 当日行读写额度，查询会直接失败（不是降速）。客户端对此做了降级：排行服务不可用时照常开箱，只是不上榜。
- 榜单只展示今日；每账号每天一条成绩（主键约束），同分按提交先后排名。
- 服务端只保存 GitHub 用户名、分数、稀有度与时间，不保存访问令牌；令牌只在请求头里用于确认身份。
